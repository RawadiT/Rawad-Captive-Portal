# دليل الأمان والعزل — نظام Captive Portal

## 1. مبدأ المنع الافتراضي (Default Deny)
- الاتصال بشبكة Wi-Fi لا يمنح أي صلاحية للإنترنت.
- تُفرض المصادقة عبر MikroTik HotSpot وFirewall في `ether10`.
- في حال توقف Backend أو تعطله، لا يحصل أي جهاز غير مصادق عليه على الإنترنت.

## 2. عزل الشبكة ومنع التجاوز
- **عزل شبكة الموظفين:** قاعدة `drop` في `forward` تمنع أي مرور من `ether10` (الضيوف) إلى `ether9` (الموظفين).
- **عزل لوحة الإدارة:** منفذ لوحة الإدارة (`3001`) محجوب عن `ether10` عبر الجدار الناري.
- **حماية إدارة MikroTik:** منافذ الإدارة (`22, 23, 80, 443, 8291, 8728, 8729`) محجوبة عن `ether10` في سلسلة `input`.
- **منع تجاوز DNS:** حظر مرور TCP/UDP 53 الخارجي من `ether10` وإلزام الأجهزة باستخدام DNS الراوتر فقط.
- **حظر IPv6:** حظر مرور IPv6 (`input` و`forward`) على `ether10` لمنع تسرب الإنترنت عبر مسار بديل.

## 3. أمان التطبيق وقاعدة البيانات
- **تشفير كلمات المرور:** استخدام `scrypt` مع Salt عشوائي لكل حساب ومقارنة آمنة زمنياً (`timingSafeEqual`).
- **فصل صلاحيات المدراء:** المدير العادي لا يمكنه إنشاء أو تعديل أو تعطيل حساب المدير الرئيسي (`super_admin`).
- **سجل تدقيق غير قابل للتعديل:** محمي بـ SQLite Triggers تمنع `UPDATE` و`DELETE` على جدول `audit_logs`.
- **حماية التكرار (Race Condition):** قفل متزامن + معاملة SQLite ذرية + قيد فريد `(mac_address, baghdad_date)` يمنع منح حصتين مجانيتين في اليوم نفسه.
- **صلاحيات MikroTik المحدودة:** استخدام حساب `rawad-api` بمجموعة صلاحيات مخصصة بدون صلاحيات `winbox` أو `ssh` أو `reboot`، عبر HTTPS (`www-ssl`).
